# 构建、故障定位与恢复

版本：V1.2 | 更新：2026-08-04

## 1. 可重复的本地非 Docker 构建

```bash
./scripts/maven-command.sh -f backend/pom.xml -B clean test
npm ci
npm audit --json
npm audit --omit=dev --json
npm run openapi:update
npm run lint
npm run typecheck
npm test
npm run build
npm run openapi:check
node scripts/validate-architecture.mjs
node scripts/generate-skeleton.mjs
node scripts/validate-skeleton.mjs
./scripts/check-migrations.sh
node scripts/validate-deploy.mjs
node scripts/validate-security.mjs
bash -n scripts/backup.sh scripts/restore.sh deploy/docker/mysql-secure-entrypoint.sh
docker compose --env-file .env.example config
git diff --check
```

`./scripts/check.sh` 是全量聚合入口。它会重新执行后端干净测试、锁定 npm 依赖、OpenAPI、前端、架构、骨架、迁移、部署和安全检查。Docker CLI 存在时只做 Compose 解析，不 build/up。

## 2. OpenAPI 生成物

- 后端 `OpenApiContractExportTest` 从当前 Spring 测试上下文导出内部/供应商契约，不只检查仓库中的旧静态文件。
- 契约评审后更新使用 `npm run openapi:update`；普通门禁使用 `npm run openapi:check`。
- `npm run openapi:baseline` 会重建兼容基线，仅在经评审接受破坏性变更时使用，不得用于掩盖契约回归。

## 3. 迁移和数据故障

1. 保留失败命令、退出码、`traceId` 和首个根因日志，不删除数据或降低断言。
2. Flyway 失败时先比对 V1–V12 连续性、V1–V3及V6/V7保护哈希、MySQL 8.4 版本和 `flyway_schema_history`。不得改写已成功迁移、手工跳版或执行 Flyway `repair`。
3. 迁移修复通过新的向前版本实现，并复验空库、V3 升级、原数据保留和重启 0 待执行。
4. 不得为定位问题执行 `docker compose down --volumes`、`git reset`、`git clean` 或手工删库。

## 4. 前端、骨架和权限故障

1. 菜单/路由失配先运行 `node scripts/generate-skeleton.mjs` 和 `node scripts/validate-skeleton.mjs`，检查是否仍为 12/87/18/69。
2. 页面请求异常以当前后端导出 OpenAPI 为准，核对 path、method、request body、分页和状态 code，不在前端猜测接口。
3. 403 需区分精确功能权限、数据维度/范围和 `READONLY`；不得改成“200 或 403 均可”的宽松断言。
4. 架构门禁失败时应将 Controller 依赖收口到应用契约，不删除 `ModuleBoundaryTest` 规则，不改用 `JdbcTemplate` 绕过分层。

## 5. 备份和恢复故障

1. 备份产物必须成组保留：数据库备份、附件归档、manifest、SHA-256 和日志。
2. 恢复前先校验 SHA-256/manifest，默认拒绝非空目标；恢复必须使用隔离 Compose 项目和独立卷。
3. MySQL 健康超时、导入失败、文件校验失败、表/角色/用户/Flyway 结果不一致都必须非零退出。
4. 不得在真实隔离演练前把 shell 语法、Compose 解析或 H2 测试记录为“备份恢复通过”。

## 6. 环境验证出口

本轮已获授权创建/推送候选提交并触发 Actions/TCR，但未授权合并`main`、打正式标签或部署生产。Actions只构建三个SRM业务镜像；服务器按`deploy/STAGE1_ACCEPTANCE.md`运行含固定 MySQL/Nginx 的独立五服务。只有五服务健康、真实 MySQL 8.4迁移和备份恢复全部通过后，才可更新阶段整体验收结论。
