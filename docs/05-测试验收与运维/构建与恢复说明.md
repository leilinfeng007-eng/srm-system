# 构建、故障定位与恢复

## 可重复构建

- 后端：`./scripts/maven-command.sh -f backend/pom.xml -B clean test`，本机无全局 Maven 时自动使用 IDEA 内置 Maven。
- 前端：`npm ci && npm run lint && npm run typecheck && npm test && npm run build`
- OpenAPI：后端测试后运行 `npm run openapi:check`；契约评审更新使用
  `npm run openapi:update`，兼容基线重置必须显式使用 `npm run openapi:baseline`
- 架构：`node scripts/validate-architecture.mjs`，检查零直接 JdbcTemplate、MyBatis 分层、
  二级缓存关闭、Caffeine 边界和双 OpenAPI 生成产物
- 骨架：`node scripts/generate-skeleton.mjs && node scripts/validate-skeleton.mjs`
- 数据库：`./scripts/check-migrations.sh`
- Flyway 有效依赖：
  `./scripts/maven-command.sh -f backend/pom.xml -B dependency:tree -Dincludes=org.flywaydb:flyway-core,org.flywaydb:flyway-mysql`
- 持久化/缓存有效依赖：
  `./scripts/maven-command.sh -f backend/pom.xml -B dependency:tree '-Dincludes=com.baomidou:*,org.mybatis:*,org.springframework:spring-jdbc,com.github.ben-manes.caffeine:*'`
- Compose：`docker compose --env-file .env.example config`
- 生产Compose：`docker compose --env-file deploy/.env.prod -f deploy/docker-compose.prod.yml config`

## 失败处理顺序

1. 保留失败命令、退出码和日志中的首个根因。
2. 依赖失败先核对 JDK/Node/Maven 版本与锁文件，不删除用户数据。
3. Flyway 失败先核对 core/mysql 有效版本、数据库版本和迁移历史；不得改写已经成功应用
   的迁移，也不得通过过滤日志或降低日志级别隐藏兼容性警告。调整版本后必须复跑真实
   MySQL 8.4 空库、重复启动和保留数据卷的容器重建。
4. 菜单/路由失败运行骨架校验，以机器清单定位重复或缺失项。
5. 容器失败查看单服务日志和健康检查，不执行 `down -v`。
6. MyBatis 异常先核对 Entity/Mapper/XML 参数绑定与模块依赖；不得改用直接 JdbcTemplate
   绕过。缓存异常核对 key 和失效入口，不得启用 MyBatis 二级缓存。
7. OpenAPI异常先核对profile和`springdoc.*.enabled`，再运行后端导出测试和
   `npm run openapi:check` 定位规范、兼容性或生成漂移；生产环境应保持关闭。

阶段0不提供自动生产回滚；生产发布、备份和恢复方案在正式部署前另行评审。
