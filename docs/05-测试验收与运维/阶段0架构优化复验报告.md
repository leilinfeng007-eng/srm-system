## 2. MyBatis-Plus 全量迁移

### 2.1 实现

- 移除五处运行时代码中的 `JdbcTemplate`/`NamedParameterJdbcTemplate` 数据访问，并移除
  旧 `JdbcWorkbenchBaselineRepository`。
- 使用 MyBatis-Plus 3.5.17 建立 Entity、Mapper、Repository 契约/适配器和领域 DTO/模型
  分离；业务/应用层不依赖 Mapper 或持久化 Entity。
- 用户、角色、刷新会话、登录/操作审计、动态菜单和 workbench 连接探测均由实际 Mapper
  执行；用户权限、角色、菜单树和活动令牌等联表/条件查询进入 4 个 XML。
- Mapper XML 只使用 `#{...}` 参数，未出现 `${...}`、`<cache>` 或 `<cache-ref>`。
- `cache-enabled=false`、`local-cache-scope=statement`；Flyway 仍是唯一结构/种子管理工具。
- V1～V3 未改名、未改序、未改内容或校验和，未新增表或业务 CRUD。

## 3. Spring Cache / Caffeine

- 业务代码统一依赖 Spring Cache 注解，不直接依赖 Caffeine API。
- 阶段0只缓存按 userId 授权过滤后的动态菜单元数据；未缓存刷新会话、登录状态、权限判定
  结果或任何实时交易状态。
- 缓存名 `navigation-menus`，最大 256 项，写入后 5 分钟过期，不缓存 null，记录统计。
- 角色分配成功后按 userId 精确失效；为未来菜单/角色权限批量维护保留显式全量失效入口。
- 集成测试验证首次 miss、再次 hit、容量、TTL 和精确失效；未引入 Redis。

## 4. OpenAPI 契约与前端生成链路

- Springdoc 分为 internal 与 supplier 两组：
  - `/v3/api-docs/internal`：7 条真实阶段0 `/api/v1/**` 路径；
  - `/v3/api-docs/supplier`：仅允许 `/supplier-api/v1/**`，阶段0 `paths` 为空，不伪造业务接口。
- 规范包含同源 server、操作 summary、全局 Bearer 与 login/refresh 匿名覆盖；Redocly
  lint 为 0 error、0 warning。
- 后端测试从实际 Controller 导出确定性 JSON；受控规范和独立兼容基线位于
  `docs/04-接口与数据设计/openapi/`。
- `openapi-diff` 对当前规范执行破坏性变更检查；负向单测实际删除 workbench 操作并确认
  检测器报告 breaking change。
- `openapi-typescript` 生成内部/供应商 TypeScript paths/components，
  `openapi-fetch` 生成两个强类型客户端工厂；生成产物由 lint、typecheck 和漂移比较共同校验。
- `npm run openapi:update` 不移动既有 baseline；只有显式
  `npm run openapi:baseline` 才建立新的兼容起点。
- dev 可开启，test 默认关闭且按测试显式开启；prod 实际容器内 internal、supplier 和
  Swagger UI 均返回 404，正常认证/RBAC接口不受影响。
