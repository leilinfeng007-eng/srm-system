# 本地运行手册

版本：V1.3 | 更新：2026-08-04 | 适用：SRM V1.0 阶段1

## 1. 工具链

- JDK 17；Maven 3.9+（也可使用 `scripts/maven-command.sh` 发现的 IDEA 内置 Maven）。
- Node.js 22–24；npm 10+。
- 需运行容器时使用 Docker Compose v2。本轮因本机网络约束不执行 Docker 构建，仅做 Compose 解析；GitHub Actions只构建三个业务镜像，服务器五服务中的MySQL与Nginx使用固定官方版本或合规现有镜像。

## 2. 非 Docker 开发与门禁

```bash
./scripts/maven-command.sh -f backend/pom.xml -B clean test
npm ci
npm audit --json
npm audit --omit=dev --json
npm run openapi:update
npm run lint
npm run typecheck
npm test
npm run build
npm run openapi:check
node scripts/validate-architecture.mjs
node scripts/generate-skeleton.mjs
node scripts/validate-skeleton.mjs
./scripts/check-migrations.sh
node scripts/validate-deploy.mjs
node scripts/validate-security.mjs
bash -n scripts/backup.sh scripts/restore.sh deploy/docker/mysql-secure-entrypoint.sh
git diff --check
```

`./scripts/check.sh` 聚合上述主要门禁。它在 Docker CLI 可用时仅运行 `docker compose ... config --quiet`，不执行 build/up。

## 3. 本地 Compose 配置

1. 将 `.env.example` 复制为被 Git 忽略的 `.env`，替换所有 `CHANGE_ME` 占位值。不得提交或在日志中输出 `.env` 内容。
2. 在允许本地构建的常规开发场景，可由人工操作员执行 `./scripts/start-local.sh`；本轮验收不执行该步骤。
3. `./scripts/stop-local.sh` 只停止服务并保留 MySQL/附件卷。除非已备份且获得明确授权，不得执行 `docker compose down --volumes`。

MySQL 入口和后端敏感值策略会拒绝缺失、过短、`CHANGE_ME`、`REPLACE_WITH`及常见示例秘密。

## 4. 本地访问点（容器健康后）

- readiness：`http://localhost:8088/actuator/health/readiness`
- internal-web：`http://localhost:8088/`
- supplier-web：`http://localhost:8088/supplier/`
- 开发 OpenAPI UI：`http://localhost:8080/swagger-ui.html`
- 内部契约：`http://localhost:8080/v3/api-docs/internal`
- 供应商契约：`http://localhost:8080/v3/api-docs/supplier`

生产 profile 默认关闭 OpenAPI，Nginx 对 `/v3/api-docs` 和 `/swagger-ui` 返回 404。

## 5. 数据、附件和 SLA

- Flyway 最新版本为 V12；旧阶段0 V3 库自动执行 V4–V12。V1–V3及保守冻结的V6/V7受哈希保护，不得改写、使用 Flyway `repair` 或手工修改 `flyway_schema_history`。
- 附件根目录由 `SRM_ATTACHMENT_ROOT` 提供；容器默认 `/var/lib/srm/attachments`，测试使用 `backend/target/test-attachments`。
- SLA 扫描开关/间隔/批次：`SRM_SLA_SCAN_ENABLED`、`SRM_SLA_SCAN_INTERVAL_MS`、`SRM_SLA_SCAN_BATCH_SIZE`。
- 备份执行 `./scripts/backup.sh`；恢复执行 `./scripts/restore.sh`。恢复默认拒绝非空目标，必须先校验 manifest 和 SHA-256。

## 6. 正式部署与延期运行验证

- 生产模板：`deploy/docker-compose.prod.yml`；变量清单：`deploy/prod.env.example`；操作说明：`deploy/README.md`。
- 阶段1源码与CI验收已通过；当前取消临时 `srm-stage1-acceptance` 环境，不复制验收环境样例、不填写五项临时秘密，也不在当前正式服务器执行命令。
- `deploy/STAGE1_ACCEPTANCE.md` 与 `deploy/stage1-acceptance.env.example` 仅保留为历史安全约束和正式部署变更窗口参考，不是当前操作指令。
- 服务器部署、现有数据库升级、五服务健康、数据卷持久化及备份恢复延后至正式部署时执行并留证；当前均未验证，不阻断阶段1代码合并和阶段2任务书编制。

## 7. Windows

优先在 Git Bash 或 WSL 执行 `.sh` 脚本。PowerShell 可复制环境样例并执行 npm 命令；后端使用 PATH 中的 Maven 或 IDEA 内置 `mvn.cmd -f backend/pom.xml -B clean test`。不同平台都必须遵守不提交 `.env`、不未经授权删除数据卷的限制。
