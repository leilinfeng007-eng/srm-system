# 本地运行与恢复手册

## 启动

1. 安装 JDK 17、Maven 3.9+（可用 IDEA 内置 Maven）、Node 22/npm 10+、Docker Compose v2。
2. 复制 `.env.example` 为 `.env`，替换所有 `CHANGE_ME`。
3. 执行 `./scripts/start-local.sh`。
4. 使用 `docker compose ps` 查看健康状态。

直接执行`docker compose`也不能使用样例秘密：MySQL入口脚本与后端启动策略都会拒绝
缺失、长度不足、`CHANGE_ME`、`REPLACE_WITH`及常见示例值。

## 停止与恢复

- `./scripts/stop-local.sh` 只停止容器，MySQL 数据卷保留。
- 再次执行 `./scripts/start-local.sh` 会复用数据，Flyway 不会重复执行已成功迁移。
- 如需重置开发数据，先备份，再由操作者显式执行 `docker compose down --volumes`。该命令不可由 Agent 未经授权自动执行。

## 验证

- readiness：`http://localhost:8088/actuator/health/readiness`
- internal-web：`http://localhost:8088/`
- supplier-web：`http://localhost:8088/supplier/`
- 全量检查：`./scripts/check.sh`
- 开发OpenAPI：`http://localhost:8080/swagger-ui.html`；内部规范为
  `http://localhost:8080/v3/api-docs/internal`，供应商规范为
  `http://localhost:8080/v3/api-docs/supplier`；设置`SRM_OPENAPI_ENABLED=false`可关闭。
- 架构/契约门禁：`node scripts/validate-architecture.mjs && npm run openapi:check`。

## 生产模板

生产模板位于`deploy/docker-compose.prod.yml`，变量清单位于`deploy/prod.env.example`，
操作说明见`deploy/README.md`。生产模板使用不可变应用镜像、`prod`配置、Secure Cookie、
默认关闭OpenAPI，并通过命名卷持久化MySQL。

2026-07-23～24 已在 Apple Silicon Docker Desktop 上完成五容器、真实 MySQL 8.4、
Nginx 代理及数据卷停启专项验收；复查命令和风险见《阶段0Docker专项验收报告》。

## Windows 替代方式

优先使用 Git Bash 或 WSL 运行仓库内 `.sh` 脚本。原生 PowerShell 可使用 `Copy-Item .env.example .env`，填写秘密后执行 `docker compose up --build --detach --wait`；停止使用 `docker compose down`，默认同样保留命名卷。后端测试可通过 PATH 中的 Maven，或 IDEA 安装目录下 `plugins\maven\lib\maven3\bin\mvn.cmd -f backend/pom.xml -B clean test` 执行；前端命令与其他平台相同。
