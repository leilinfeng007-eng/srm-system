# 数据库与迁移规范

- 生产基线为 MySQL 8.4；Flyway 是结构和种子迁移的唯一权威。
- `flyway-core` 与 `flyway-mysql` 必须保持同版，阶段0固定为 11.15.0；依赖升级必须先
  核验 Maven 有效依赖树，再以真实 MySQL 8.4 空库、重复启动和数据卷持久化复验。
- 表/列使用 `snake_case`；主键 `id BIGINT`；业务编码使用独立唯一索引。
- UTC 存储；审计字段使用 `created_by`、`created_at`、`updated_by`、`updated_at`，按对象增加 `version`、`deleted`。
- 状态使用稳定英文 code；业务状态、审批状态、接口状态不得共用一个字段。
- 金额与数量使用明确精度的 `DECIMAL`，禁止 float/double。
- SQL 必须使用参数绑定；索引必须对应已说明的查询用例。
- 运行时数据访问统一使用 MyBatis-Plus 3.5.17；Spring Boot 3 starter 解析为 MyBatis
  3.5.19、mybatis-spring 3.0.5，并保持 Spring Boot 3.4.1 依赖管理。
- Entity 与 Mapper 仅属于 infrastructure；Repository 适配器负责领域转换。联表、权限树
  等复杂查询使用 Mapper XML，参数只允许 `#{...}`。
- 禁止 MyBatis-Plus DDL 自动生成或 schema 初始化；禁止 MyBatis `<cache>`、`<cache-ref>`
  及二级缓存，`local-cache-scope` 固定为 `statement`。
- 已发布 Flyway 文件不可修改；只允许新增更高版本迁移。
- `database/` 不复制结构 SQL，仅放校验、数据字典和人工运维说明。
- 阶段0只允许 10 张 `sys_*` 平台表，不创建 12 个业务域的空表。
- 自动化测试固定使用 H2 2.2.224 的 MySQL 兼容模式；它只验证迁移和代码，不替代真实
  MySQL 8.4 验收。
