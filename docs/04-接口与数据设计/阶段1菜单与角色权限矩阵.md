## 3. 角色职责

| 角色 | 功能边界 | 数据与操作边界 |
|---|---|---|
| `SUPER_ADMIN` | 阶段1启用菜单与权限 | 阶段1维度 `ALL + READ_WRITE`；仍不能穿透 69 个阶段禁用页 |
| `SYSTEM_ADMIN` | 系统治理和所需主数据协同 | 必须命中对应数据策略；不得分配 `SUPER_ADMIN` |
| `MASTER_DATA_ADMIN` | 主数据、模板、附件和批处理 | 精确维度上 `READ_WRITE`，无策略拒绝 |
| `PROCESS_ADMIN` | 流程、审批、任务和相关消息 | 只能在已授权范围配置和查看 |
| `INTERNAL_AUDITOR` | 审计、查看和导出 | `READONLY`；全部写操作由后端拒绝 |
| `INTERNAL_USER` | 工作台、本人任务/审批/消息 | `SELF`；V12 允许标记本人消息已读，他人消息仍拒绝 |
| `SKELETON_VIEWER` | 只读工作台骨架 | 无策略即拒绝数据访问 |

## 4. 权限与数据策略规则

- 权限码为 `domain:resource:action`，页面按操作精确使用 `view/create/update/enable/disable/assign/publish/submit/retry/export/import/manage` 等动作，不用一个宽权限代替启停或授权。
- 权限目录从数据库返回真实 ID；角色菜单、权限、用户和数据策略四个集合独立读写，不相互清空。
- 数据范围：`ALL / ORG / SELF / DENY`；维度：`ORGANIZATION / PURCHASING_ORGANIZATION / PLANT / CATEGORY / OWNER / SUPPLIER`；模式：`READ_WRITE / READONLY`。
- 同一授权路径必须同时命中功能权限、数据维度、范围和操作模式；多角色不得交叉拼接宽范围与写权限。
