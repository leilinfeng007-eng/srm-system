# 阶段1平台与数据底座详细设计

版本：V1.2 | 更新：2026-08-04 | 状态：候选源码本地门禁通过，待最终环境验收

> 阶段1候选源码及本地非 Docker 门禁完成；Actions/TCR 与服务器五服务、MySQL 迁移及备份恢复尚未形成完整真实证据，阶段结论为“待最终环境验收”。

## 1. 架构与阶段边界

- 模块化单体保持 `api → application → domain ← infrastructure` 依赖方向。Controller 仅做协议转换、校验和鉴权，不直接依赖 Mapper、持久化实体或基础设施实现。
- `system` 承载身份、RBAC、数据策略、审批、任务、消息和通用治理；`masterdata` 承载组织树和主数据；`workbench` 通过公开应用契约聚合。
- 前端路由清单和后端菜单树双重约束：12 个一级域、87 个功能项，阶段1仅 18 个启用，69 个后续项不注册安全组件、不出现在菜单且无法通过直接路由进入。

## 2. 组织与身份

- `md_organization` 严格限定 `GROUP → COMPANY → BUSINESS_UNIT → PLANT → WAREHOUSE`；工厂/仓库扩展与组织节点同事务创建，不重复落库。
- 部门必须归属有效组织，岗位必须归属有效部门；用户主组织、主部门、主岗位必须同链路匹配。
- 初始密码由创建结果一次性返回，用户首次登录受 `mustChangePassword` 限制；调岗和角色挂载记录历史。
- 更新、启停和授权使用乐观锁或 CAS，冲突不被静默覆盖。

## 3. 功能权限与数据范围

- 一条有效授权路径必须同时满足：功能权限、角色、数据范围、数据维度和操作模式。
- 范围为 `ALL / ORG / SELF / DENY`，操作模式为 `READ_WRITE / READONLY`；`OWNER` 不是范围类型，`READONLY` 不与范围混用。
- 读取可合并各合格角色各自范围；写入只合并同一角色上同时具备精确权限、`READ_WRITE` 和目标范围的路径，防止“全局只读 + 局部读写 = 全局读写”。
- 无策略默认拒绝。列表、详情、写入、导入导出、批任务、附件、审计和接口任务均由后端执行范围校验。
- 角色的用户、菜单、接口权限和数据策略独立读写；授权更新事务化并精确失效权限缓存。非超级管理员不能分配 `SUPER_ADMIN` 或提升自身。

## 4. 审批、任务、SLA 与消息

- 流程定义按 `process_code + version` 版本化，发布版不可覆盖；发起时冻结审批人快照。
- 仅当前节点可操作，前节点完成后才激活下一节点；非当前审批人、自批、越序、重复处理和终态撤回被拒绝。
- 只有最终节点通过才触发必须已注册的业务回调。回调、实例、节点、任务和消息处于同一事务边界，失败整体回滚，最终回调幂等。
- 超期扫描使用 CAS 和幂等键，同一超期事件只生成一条消息。消息已读同时校验功能权限和收件人归属。

## 5. 通用治理

- 字典/字典项、参数/版本、编号规则、文档模板、附件、批量导入导出和审计形成可用闭环。
- 编号分配使用数据库原子更新，不依赖 JVM `synchronized`。
- 附件扩展名、客户端 MIME 和文件签名三者一致才可入库；存储键由服务端生成，落盘后入库失败会清理孤儿文件，已删除附件普通读取返回 404。
- 导入导出支持 8 类阶段1数据，有行级校验、成功/失败计数、错误结果附件、幂等键和重试状态。
- 审计覆盖组织身份、角色/数据策略、通用治理、主数据、审批、附件、Inbox/Outbox 和批任务；密码、Token、密钥和附件内容不记录。

## 6. 主数据与集成

- 采购组织、交付地点、品类、单位、币种、税码和物料统一使用来源、外部标识、外部版本和同步时间字段。
- Inbox 通过真实处理器注册表执行业务更新；重复事件幂等，旧版本标记忽略，失败可重试。
- Outbox 使用原子 CAS 领取，明确 `READY/PROCESSING/SUCCEEDED/FAILED/DEAD` 和下次重试时间；手工重试将合格失败事件恢复为可领取状态。

## 7. 安全、测试与已知边界

- SQL 参数化，统一 `ApiResponse/PageResult`，日志携带 `traceId`；OpenAPI 默认在生产关闭，内部端与供应商端契约分离。
- Caffeine 缓存声明容量和 TTL，权限变更有精确失效入口；禁用 MyBatis 二级缓存。
- 本地 H2 测试已验证 V1–V12 空库、V3 升级和重启无待执行迁移；这不替代 GitHub Actions 或服务器上的真实 MySQL 8.4 验收。
- V1–V3 有阶段0执行证据；V6/V7 此前未进入 Git 提交且没有可核验的冻结环境执行证据，但无法反证外部临时库执行，因此候选起锁定其 SHA-256。修正只能新增迁移，禁止 Flyway `repair`。
- Actions 只构建 `backend`、`internal-web`、`supplier-web` 三个 `linux/amd64` 业务镜像；服务器以独立 `srm-stage1-acceptance` 项目运行三个业务镜像及固定版本 MySQL、Nginx，命令见 `deploy/STAGE1_ACCEPTANCE.md`。
- P2 延期：超期扫描批次动态化、附件病毒扫描引擎集成、大规模组织树全量加载性能优化。
